# 통합 설정 API와 실제 입력 검증

실행 소스는 `6256f7eb0655676d11427dfe118c4821eb022ac6`이다.
설치 보정·A/B 개별 단면·종합 보정곡선·가중치를 같은 설정 revision으로 갱신하는
[통합 API](CONFIGURATION_API.md)를 Pi의 실제 SDK 입력과 ARM64 Docker에서 확인했다.

## 회귀와 이미지

- 로컬 및 Pi의 네트워크 차단·읽기 전용 격리 Docker에서 각각354개 회귀 통과.
- 린트, sdist/wheel 빌드와 새 모듈 포함 확인.
- 해당 소스의 플랫폼·카메라 CI와 SDK AddressSanitizer 검사, ARM64 이미지5종 빌드 통과.
- 독립 코드 검토에서 중요한 미해결 결함 없음.
- 실제 데이터·설정·접속 정보·인증 정보는 저장소에 추가하지 않음.

## 실제 SDK 입력의 격리 기능 시험

운영과 같은 드라이버 UDS를 읽지만 별도 설정·상태·큐·제어 폴더와 수신기를 사용했다.
시험 수신기는 계약 검증 후 ACK를 반환하며 운영 백엔드 DB 저장 시험과 구분한다.

1. 기본 프로필의 A/B 설치, 독립4bin 단면, 항등 곡선과0.5/0.5 가중치를 API로 요청했다.
   백엔드 ACK와 데이터 서비스3개의 적용 후 APPLIED를 확인했다.
2. 새 revision으로 설치 Z를10mm 조정하고 보정 버전을 바꿨다. 단면은200mm×5bin,
   공간 편차250mm로 바꾸고 곡선의 중간 점을 A=0.45, B=0.55, 가중치를0.4/0.6으로 변경했다.
   같은 API의 APPLIED와 실제 계산 결과에 반영된 가중치·종합 수식을 확인했다.
3. API 컨테이너를 재시작하고 활성 설정·새 revision·작업 적용 상태가 유지되는지 확인했다.

| 기능 결과 | 기본 설정 | 변경 설정 |
|---|---:|---:|
| 정기 측정 메시지 | 37 | 41 |
| 좌표를 포함한 정기 측정 점 | 57,600 | 64,000 |
| 수치 종합 결과 | 32 | 37 |
| A/B 독립 단면 포함 | 확인 | 확인 |
| DEFAULT_SETTINGS 및 LIMITED 표시 | 확인 | 확인 |
| 가중치와 종합 수식 대조 | 확인 | 확인 |

설정 전환을 포함한 기능 시험에서 판단 묶음1개에 해당하는11개 메시지의 폐기 누계가 관측되었다.
발생 시점을 세부 계측하지 않아 전환 자체가 원인이라고 단정하지 않는다. 이 시험을 무손실로 표현하지 않는다.

후속 재현에서 저장 지연 시 대기열 덮어쓰기 경로를 확인하고 수정했다.
동일 지연·600초 실제 입력 재시험: [판단 대기 수정 검증](JUDGMENT_BACKPRESSURE_VALIDATION_2026-11-08.md).

변경 설정으로 다시 기동하고 준비 구간 후60초를 별도 관측했다.
관측·판단 대기·저장 손실 카운터의 추가 증가는0이었고 전송 대기는8건에서0건으로 줄었다.
해당 생성 시각 구간의 정기 측정·판단은 각60건이었다. 생성 간격 중앙값은 둘 다1.001초,
p99/최대는 각각1.050초와1.019초였다. 짧은 추가 시험이며 장시간 무손실을 보장하지 않는다.
이 수치는 generated_at 간격이다. 수신기의 검증·해시 계산 뒤 기록 시각을 네트워크 도착 시각으로 해석하지 않는다.

## 운영 적용과 실제 백엔드 전달

전처리·uplink·오케스트레이터와 설정 API를 위 소스 이미지로 교체했다.
기존 큐·제어 상태·인증 파일·드라이버·카메라를 유지하고 이전 이미지와 정지 시점 큐를 Pi에 확보했다.
네 컨테이너의 healthy와 활성 설정 적용을 확인했다.

실행 중 시뮬레이터 환경과 공개 환경 정의의 canonical JSON SHA-256은
`048e85578e56488707941c902cc512012a229e7d7d71d5339a9831fc3ac3c6a5`로 일치했다.
그 환경의 설치 기본값만 운영 API로 요청하고 실제 백엔드 저장 ACK 및 서비스3개의 APPLIED를 확인했다.
활성 revision은 `synthetic-default-installation-v1`, A/B 보정 버전은
`default-simulator-installation-v1`이다. SDK source revision은 변경하지 않았다.

실제 백엔드가 저장한 정기 측정에서 같은 A 스캔의 원래3점만 서버 측 발췌했다.
센서·스캔·메시지 ID, 시각, 원래 index·점 수·거리·각도·품질·XYZ를 유지하고,
3점 모두 해당 R/t로 재계산한 정수 좌표와 일치함을 확인했다.
이 발췌 JSON과 필드 설명 MD는 별도 로컬 회신 폴더의 두 파일이며 공개 Git에는 포함하지 않는다.

실제 샘플의 시계는 UNSYNCED, offset은null이다. 좌표 계산 가능 여부와 외부 UTC 정합 보장은 별개다.
z는 반사점 world Z이며 현재 바닥 Z=0에서만 바닥 상대 높이와 수치상 같다.
필터·중앙값·보간 후 bin 바닥을 뺀 판단 height_mm과 구분한다.

현재 운영 백엔드는 judgment·section_profiles·fusion_result를 거부한다.
따라서 전체 판단 기본값은 조회·변경 가능한 프로필로 준비하고 격리 수신기에서 검증했지만,
운영에는 백엔드가 수용하는 설치 보정만 활성화했다. 이 제한을 우회하여 ACK 전 전체 모델을 적용하지 않는다.
백엔드가 확장 계약을 수용하면 같은 통합 API로 전체 프로필을 요청할 수 있다.

배포 전 운영 오케스트레이터에는 폐기 누계1건이 있었고 기록을 보존했다.
재시작 후 새 인스턴스의0을 전체 운영 이력의 손실0으로 해석하지 않는다.
기존 격리1건도 삭제하지 않았다. 설정 적용 시 관측 구독 준비·구버전 입력 경계 카운터는 별도로 유지한다.
