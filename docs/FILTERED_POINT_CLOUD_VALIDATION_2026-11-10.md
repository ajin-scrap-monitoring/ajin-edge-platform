## 확인 결과

로컬과 Pi ARM64 Docker에서 각각413개 테스트를 통과했다. Ruff 검사와 wheel/sdist 빌드도 통과했다.
필터의 중복 스캔·각도 동률·일대일 대응·이력 부족·설치 보정·무효값·시간 만료,
설정 API의 인증·ACK 대기·거부 시 이전 설정 유지·동일 본문 재전송을 검사했다.
정수 자리에2.0이 들어오는 경우의 설정 거부와 두 센서 계산 완료 후 공통 만료 검사도 포함한다.
기존 테스트370개를 유지하고43개를 추가했다.

Pi에서는 기존 의존성을 사용한 별도 후보 이미지에 대상 소스를 복사해 검사했다.
운영 이미지 교체·설정 활성화·운영 큐 변경은 수행하지 않았다.

## Pi 실제 입력 시험

Pi 전처리기의 기존 관측 UDS를 별도 컨테이너에서 구독했다. 네트워크를 차단하고
운영 설정과 소켓을 읽기 전용으로 연결했다. 운영 설정에서 복제한 판단 설정에만
point_cloud를 추가했으며 실제 백엔드 주소로 전송하지 않았다.
각 시각의 동일한 이력 스냅샷으로 기존 판단과 신규 판단을 비교했다.
신규 STATE는 메모리의 모의 HTTP 수신기로 보내 계약 검증과 ACK를 확인했다.
실시간 점 배열과 운영 설정·토큰은 검증 문서나 공개 저장소에 포함하지 않았다.

## 합성 부하 시험

Pi ARM64 Docker를 CPU1개·메모리512MiB로 제한했다.
센서별800점·5스캔·128개 단면bin을 사용한20회 시험에서 계산 중앙값258.090ms,
최대317.034ms였다. 모든 점이 유효했고 STATE 크기는117435bytes였다.
부하 스크립트는 `tools/benchmark_section_judgment.py --point-cloud --iterations 20`이다.
이 수치는 해당 입력과 시험 환경의 결과이며 입력 크기와 시스템 부하에 따라 달라진다.

## 전달 및 활성화 상태

새 배열은 기존 assessments 경로의 STATE.filtered_point_clouds에 추가한다.
원본 점과 기존 대표 높이를 유지한다. 새 설정 객체가 없으면 새 필드를 보내지 않는다.
운영은 기존 설정을 유지하며 새 배열은 아직 운영 백엔드에 보내지 않는다.
백엔드 담당자가 configurations의 judgment.point_cloud와 STATE.filtered_point_clouds를
수용·보존·조회할 수 있도록 규격을 전달한 뒤 기존 제어 API로 활성화한다.
백엔드 저장소의 코드·Git·PR·배포는 변경하지 않았다.
