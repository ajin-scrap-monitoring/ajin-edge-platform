# 설계 결정과 한계

| 선택 | 이유와 한계 |
| --- | --- |
| 공식 SDK와 gRPC, ROS 미사용 | 고정된 센서 처리와 배포 범위를 단순화한다. ROS 도구·노드 생태계 연동은 포함하지 않는다. |
| ScanFrame의 instance_id·config_revision | 재시작과 설정 변경을 프레임 자체에서 구분한다. 구형 producer도 필수 값을 전달하도록 갱신해야 한다. |
| UUID 측정 식별자 | 서버는 불투명한 고유 문자열로 취급한다. 다른 ID 형식을 강제하면 계약 조정이 필요하다. |
| 단일 센서 전용 보정표 | 두 센서 표를 재사용하지 않는다. 별도 표가 없으면 센서 장애 시 INVALID를 출력한다. |
| 공통 Python 패키지와 독립 프로세스 | 계약 검증을 공유하되 서비스별 이미지를 실행한다. 공통 코드의 완전 독립 릴리스는 추가 설계가 필요하다. |
| bin 정렬·전체 높이 직사각형 마스크 | 지원하지 않는 부분 높이·다각형은 보정 오류로 거부한다. 복잡한 형상은 면적 처리 확장이 필요하다. |
| monotonic 기반 Outbox 보존 나이 | UTC 보정으로 데이터를 조기 폐기하지 않는다. 정지 시간은 제외되어 달력 기준 24시간 상한을 보장하지 않는다. 건수·용량 상한은 별도로 적용한다. |

실장비 검증을 대신하는 가정이 아니다. [검증 범위](VALIDATION.md)와 [운영 절차](OPERATIONS.md)를 참고한다.
