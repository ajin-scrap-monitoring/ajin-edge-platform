# 오케스트레이션 단면 및 적재율 판단

## 경로와 책임

전처리는 합의한 선택 구간의 원본 점 순서, index, 거리, 각도, 품질을 유지해 PERIODIC으로 전송한다.
오케스트레이션은 모든 관측의 별도 사본을 받아 판단한다. 품질이 낮아 판단에서 제외된 점도 원본과
EVIDENCE에서 삭제하지 않는다. 기존 measurements 형식과 선택 정책은 변경하지 않는다.

구현 위치는 `ajin_edge.v2.judgment.SectionJudgment`이며 기존 v1 전처리 전체를 복구하지 않는다.
`configuration.judgment`에 명시한 기하와 임계치를 사용한다. 설정이 없으면 계산 미설정,
미검증이면 미검증, 설치 보정이 없으면 보정 누락으로 보고한다. 운영 설치값을 자동으로 만들지 않는다.

## 계산 순서

1. 센서별 최근 관측을 최대 8개 보관한다. 보관 수, 최소 유효 스캔 수와 시간 창은 설정한다.
   인스턴스/시계 변경이나 시간 창을 넘는 수집 공백이 발생하면 해당 센서 이력을 분리한다.
2. 1초 이내의 동일 단조 시계에서 A/B 최신 쌍을 고른다. 시각 차이는 설정값 이하이며 최대 100ms다.
   최신 쌍은 두 획득 시각 중 이른 시각을 최대화하고, 동률이면 차이가 작은 쌍이다.
   선택한 센서별 시각 이후의 관측을 과거 단면에 섞지 않는다.
3. 원본 거리·각도와 검증된 R, t로 반사점 실수 좌표를 재계산한다. 전송된 정수 좌표를 재입력하지 않는다.
   품질, 거리, SDK 무효 사유, 단면 평면 거리, 높이 범위를 검사한다.
4. 공통 단면 기준선의 축 방향 위치로 일정 폭 bin을 정하고 스캔마다 z 중앙값을 계산한다.
   선택적 공간 필터는 주변 bin 중앙값과의 편차가 설정값을 넘는 고립 bin을 제외한다.
   이웃 필터는 비활성 마스크를 건너지 않는다.
5. 센서별 각 bin에서 최근 스캔의 중앙값을 계산한다. 최소 유효 스캔 수보다 적으면 해당 bin은 비어 있다.
6. 같은 bin에 A/B가 함께 있으면 높이 차이를 검사한다. 허용 차이를 넘으면 CONFLICT로 남긴다.
   합치면 두 값의 중앙값, 한 센서만 관측한 bin은 그 값을 사용한다. A/B 시각 쌍과 센서별 이력은
   모두 필요하며, 한 센서 전체가 없을 때 수치 적재율을 생성하지 않는다.
7. OBSERVED 양끝 사이의 짧은 UNAVAILABLE 구간만 선형 보간한다. 양끝 외삽, 긴 빈 구간,
   MASKED와 CONFLICT를 넘어선 보간은 하지 않는다. 보간된 점은 원본 측정점으로 취급하지 않는다.
8. 바닥을 뺀 높이는 0~bin 상한 높이로 제한한다. 높이 여유 허용량도 설정에 명시한다.
   이는 점유 높이 계산의 경계 처리이며 원본 좌표나 거리를 변경하지 않는다.

## 단면과 적재율의 수학적 의미

단면 축은 XY 평면의 단위 벡터 u이고 원점은 o다. 점 p의 축 좌표는 `(p_xy - o) · u`다.
축의 수직 방향 거리도 검사하여 다른 평면의 측정점을 같은 단면으로 합치지 않는다.
모든 높이는 공통 좌표계의 Z 방향이다.

활성 bin i의 폭을 w, 바닥과 상한을 f_i, c_i, 판단 높이를 h_i라 할 때:

```text
단면 적재 면적 = Σ w × h_i
단면 용량 면적 = Σ w × (c_i − f_i)
단면 면적비 = 단면 적재 면적 / 단면 용량 면적
```

마스크는 두 면적의 계산 영역에서 제외한다. 활성 bin에 미해결 빈 구간이나 충돌이 있으면 전체 면적과
면적비는 null이며 일부 관측으로 전체를 부풀리지 않는다. coverage_ratio는 보간 전 직접 관측 bin 비율이다.

면적비는 그 단면의 비율이며 용기 전체의 부피 적재율과 같다고 가정하지 않는다. `fill_calibration`은
`[단면 면적비, 보정 적재율]`의 단조 곡선이다. 검증된 판단 설정에서만 선형 구간 보간으로
`fill_estimate.ratio`를 산출한다. 곡선이 없으면 단면은 제공하되 적재율은 null이다.
검증 표시는 수학 코드가 자동 판정하지 않는다. 실제 설치·운영 적용 검증을 수행한 설정에만 VERIFIED를 준다.

## 등록과 출력

- 등록 JSON에 선택적 `judgment`를 추가했다. 임계치·시간 창·단면 기준·마스크·보정곡선이 등록되므로
  같은 config_revision의 내용을 변경할 수 없다. method_version도 설정을 추적하는 식별자다.
- 판단 JSON에 선택적 `section_profile`을 추가했다. bin별 바닥·상한·판단 높이·근거 센서와
  OBSERVED / INTERPOLATED / UNAVAILABLE / MASKED / CONFLICT를 제공한다.
- `area_mm2`, `capacity_area_mm2`, `area_ratio`와 `coverage_ratio`를 구분한다.
- `sensor_stats.retained_points`는 점별 필터 통과 수다. 공간 bin 제거 수는 별도
  `spatial_rejected_bins`이며 보간 결과는 원본 점 수에 합산하지 않는다.
- 적재율은 기존 `fill_state`, `fill_estimate.ratio`, `fill_estimate.method_version`을 사용한다.
  capability는 계산 코드 유무와 입력 가용성을 구분한다. 설정/곡선 미검증은 NOT_VALIDATED,
  활성 방법에서 데이터가 부족하면 capability는 ENABLED이지만 decision_state는 UNAVAILABLE이다.
- 짧은 보간을 사용하면 LIMITED와 INTERPOLATED_BINS를 보고한다. 가림·수거·영상 기능은 여전히
  NOT_IMPLEMENTED이며 단면 고립점을 자동으로 집게 사건으로 만들지 않는다.

공개 예시는 [설정](../examples/v2/judgment-configuration.json)과
[판단 결과](../examples/v2/judgment-assessment.json)에 있다. 설정은 의도적으로 UNVERIFIED다.
판단 결과는 테스트에서만 VERIFIED로 바꾼 동일한 합성 기하의 결과이며 현장 보정 자료가 아니다.

## 근거 전달과 독립 실행

로컬 Bundle begin으로 판단 본문과 근거 메시지 ID·해시 목록을 등록해 참조 스캔을 먼저 보호한다.
EVIDENCE는 기존 Enqueue로 한 건씩 저장한 뒤 Bundle commit으로 실제 저장 본문·해시·참조를
대조하고 판단을 마지막에 저장한다. 큰 스캔 여러 개를 한 RPC에 합쳐 기존 내부 전송 한도를
넘기지 않는다. 용량 부족으로 자기 근거를
밀어내며 판단만 수락하지 않는다. 중간 실패 시 일부 근거는 남을 수 있지만 의존 판단은 저장하지 않는다.
판단 저장 후에는 기존 참조 보호가 이어지고 임시 보호를 해제한다. 비정상 종료의 임시 보호는
최대 300초 뒤 해제되며 이미 저장된 근거의 정상 전송은 계속된다.
각 EVIDENCE는 원래 scan_id, 획득 시각과 모든 선택 점을 유지하며 assessment_ids로 판단과 연결한다.
사용 스캔은 판단의 evidence.scans와 observed_from/to에도 명시한다.
원격 저장을 확인하지 않은 근거는 추가 전송한다. 원격 HTTP 도착 순서는 보장하지 않는다.
서버는 기존 계약대로 참조를 나중에 연결할 수 있어야 한다.

계산은 별도 worker에서 실행하고 원본 전처리나 상태 RPC를 기다리지 않는다. 계산 완료 전 입력 만료도
재검사한다. 센서별 이력 최대 8개, 진행 중 전달 묶음 1개와 대기 판단 묶음 1개로 메모리를 제한한다.
한 묶음은 최대 16개 EVIDENCE와 판단 1개다. 진행 중 묶음은 대기 큐 교체로 폐기하지 않는다.
로컬 근거 거부 시 그 묶음의 판단을 보내지 않는다. 내부 IPC의 기존 64MiB 보호 한도는 유지한다.
대기 초과로 버린 남은 메시지 수를 local_dropped_messages에 보고한다.
전송 성공 후 고정 100ms 대기를 제거해 근거 묶음이 초당 10요청 상한에 막히지 않게 했다.
실패 재시도, 인증 중단과 백오프는 그대로 유지한다.

## 백엔드 반영 및 적용 순서

추가 경로는 없다. `/api/edge/v2/configurations`의 judgment와 `/api/edge/v2/assessments`의
section_profile을 확장 스키마대로 수용하면 된다. measurements, ACK와 상태 경로는 유지한다.
백엔드가 엄격한 이전 스키마를 사용한다면 새 설정을 켜기 전에 이 두 필드의 수용을 먼저 확인한다.
그 후 설치 보정·판단 설정을 새 config_revision으로 등록하고 저장 ACK 후 활성화한다.
오케스트레이션의 근거 묶음은 새 로컬 Bundle 메서드를 사용하므로 전송 서비스를 먼저 갱신한다.
기존 운영의 주소·토큰·큐를 예제 값으로 덮어쓰지 않는다.

## 검증

회귀 검사는 원본 보존, 단면 면적과 보정곡선, 공간·시간 중앙값, 짧은 보간과 금지 경계,
A/B 상호 보완과 충돌, 만료·인스턴스·시계 변경, 근거 전달과 세 서비스 연동을 확인한다.
합성 입력의 정확성과 실행 시간은 현장 정확도 검증과 별도다.
`tools/benchmark_section_judgment.py`는 센서별 800점, 센서별 최근 5스캔과 128개 bin의
판단 및 근거 구성 시간을 확인한다. 이 도구는 합성 예시만 읽고 운영 설정을 사용하지 않는다.

2026-11-08 검증에서 Windows 전체 256개와 린트, Pi ARM64의 읽기 전용 격리 Docker 환경에서
전체 256개가 통과했다. Pi 시험은 네트워크를 차단하고 CPU 1개, 메모리 512MiB로 제한했다.
동일 제한의 합성 성능 검사 20회에서 판단 및 근거 11개 메시지 구성 시간은 중앙값 198.693ms,
최대 226.716ms였다. 이 수치는 원격 HTTP 저장 처리량이나 현장 적재율 정확도를 보증하지 않는다.
