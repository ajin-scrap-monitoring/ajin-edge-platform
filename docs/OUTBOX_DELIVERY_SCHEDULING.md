# Outbox 저장·송신 처리

이 문서는 v2 엣지 내부 구현을 설명한다. 백엔드 요청 경로, payload, ACK 규격은 변경하지 않는다.

## 저장과 수거

- 디스크 쓰기는 단일 저장 executor에서 직렬 처리한다.
- 판단이 참조하는 스캔 집합은 판단 추가·상태 변경·삭제·ACK 시 무효화하여 다시 계산한다.
- 저장 공간이 충분한 새 쓰기는 수거를 반복하지 않는다. ACK 처리와 주기 수거는 유지하며, 공간이 부족하면 수거 후 기존 용량 확보 정책을 실행한다.
- 검증 완료된 canonical payload 바이트를 파일 envelope에 그대로 사용해 점 배열의 중복 직렬화를 피한다. 저장 파일 바이트 형식은 동일하다.
- 수거는 ACK된 항목만 순회한다. ACK되지 않은 전체 대기 목록을 매번 수거 대상으로 검사하지 않는다.
- 활성 lease 또는 ACK되지 않은 판단이 참조하는 근거는 기존 규칙대로 보호한다.
- 물리 파일 할당량은 자체 쓰기·교체·삭제마다 갱신한다. 일반 운영 상태 조회는 이 값을 사용하고, 약 60초마다 전체 파일 감사로 조정한다. 쓰기 전에도 감사 주기를 확인한다.
- 대기·격리 건수와 대기 payload 바이트는 추가·상태 변경·삭제 시 증감하며, 시작 시 저장 파일에서 재구성한다. 상태 조회마다 전체 대기 목록을 순회하지 않는다.
- 관리용 `stats()` 기본 호출은 강제 감사를 유지한다. 빈번한 내부 RPC와 주기 보고는 `audit=False`를 사용한다.
- 저장 상한·예약 공간·용량 부족 시 처리 정책은 그대로다. 이 변경은 대기 데이터 삭제나 상한 확대를 통한 적체 해소가 아니다.

## 송신 선택과 공정성

- 최신·최구·설정 우선 선택은 인덱스를 사용한다. 오래된 인덱스 항목은 상태·세대·pin을 검사해 제외하고, 제한을 넘으면 재구성한다.
- 동시에 선택·송신·ACK 저장 대기 중인 저장 메시지는 최대 16개다. 한 선택 작업만 실행하고, 영구 ACK로 해제된 자리에 다음 메시지를 비동기로 준비한다.
- 한 회차는 상태 메시지를 포함해 최대 32회 송신 또는 2초의 새 송신 시작 구간으로 제한한다. 구간 종료 후 이미 시작된 HTTP·ACK·선택 작업을 정리하며, 남은 미송신 pin을 해제한다. 따라서 전체 회차 완료 시간이 2초라는 의미는 아니다.
- 설정 메시지를 우선한다. 그 다음 최신 PERIODIC과 최신 STATE에 각각 한 번의 선택 기회를 준다. 남은 자리는 최신·최구 교대 정책을 사용한다.
- 이는 적체 중 실시간 원본·판단이 근거 메시지에 밀리지 않도록 하는 정책이다. 모든 과거 메시지나 모든 HTTP 도착 간격이 1초 이내임을 보장하지는 않는다.
- 네트워크 요청은 동시에 최대 6개다. 첫 저장 선택 이후 다음 선택·ACK 기록·HTTP를 함께 진행해, 이전 묶음의 가장 느린 HTTP 응답이 다른 슬롯의 다음 묶음을 막지 않게 한다.
- 인증 실패·설정 오류·재시도 응답이 있으면 새 송신을 중단한다. 이미 시작한 요청은 기존 ACK 처리 규칙에 따라 정리한다.

## ACK 영구 저장

- 원격 ACK를 최대 8건씩 묶어 저장한다. 회차가 끝나면 8건 미만의 ACK도 저장한다.
- ACK 저장 작업은 한 번에 하나이며, HTTP 슬롯 처리와 별도 비동기 작업으로 진행한다.
- 원격 성공 응답만으로 원본을 삭제하거나 ACK 확인을 공개하지 않는다. 기존 atomic metadata 저장이 성공해야 ACK 상태를 반영하고 pin을 해제한다.
- 취소·저장 실패·프로세스 종료가 원격 수신과 로컬 ACK 영구 기록 사이에 발생하면 같은 메시지를 재전송할 수 있다. 동일 message_id와 내용으로 기존 중복 ACK 계약을 사용한다.
- 선택 중 오류와 취소 시에는 뒤늦게 선택된 pin도 정리한다. 진행 중인 ACK 저장이 있으면 정리가 끝난 후 나머지 pin을 해제한다.
- 보관 중인 근거와 판단의 참조 관계 및 재시작 복구 형식은 유지한다.

## 로컬 계측

송신 서비스의 로컬 상태 파일에 다음 누적 집계를 기록한다. 서비스 재시작 시 이 집계는 초기화된다. Outbox의 영구 손실 카운터와는 별개다.

- `storage_metrics`: 작업별 호출 수, 실행 시간 합계·최댓값, executor 대기 시간 합계·최댓값. 시간 단위는 ms다.
- `http_delivery`: 전송 종류별 호출 수, send 전체 시간 합계·최댓값, ACK·오류 분류별 건수. 직렬화·통신·응답 해석을 포함하며, 저장 executor 대기는 포함하지 않는다.

기간 평균은 같은 서비스 instance의 누적 합계 차이를 호출 수 차이로 나누어 계산한다. 최대값은 해당 instance의 누적 최대이며, 이를 기간 p99로 해석하지 않는다. 원본 배열·토큰·운영 주소는 집계에 포함하지 않는다. 이 진단 필드들은 백엔드 `edge_status` payload에 자동 추가되지 않는다.

## 회귀 검증

`uv run --frozen pytest`로 전체 테스트를 실행한다. 관련 테스트는 다음 동작을 검증한다.

- 판단 ACK 전 근거 보호, ACK 후 수거, 재시작 복구.
- 반복 재시도·인덱스 재구성 중 pin과 대기 항목 유지.
- 저장이 느려도 HTTP 슬롯 재충전, 동시 요청 6개 제한.
- ACK 저장과 다음 선택이 겹친 상태의 취소 이후에도 영구 ACK 또는 원본 재전송 가능성을 유지한다. 시간 제한 후 도착한 선택 결과는 송신하지 않고 해제한다.
- 적체 중 최신 PERIODIC·STATE 선택 기회.
- 빈번한 상태 조회에서 감사 비용 제한과 주기적 실제 할당량 조정.
