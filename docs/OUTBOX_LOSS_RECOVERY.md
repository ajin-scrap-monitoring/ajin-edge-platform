# Outbox 손실 경고 자동 복귀

## 목적

`storage.lost_messages` 등 과거 손실 기록을 보존하면서 현재 활성 `OUTBOX_DATA_LOSS`를 별도로 관리한다. 백엔드 메시지 스키마·API와 큐 보관 정책은 변경하지 않는다.

## 복귀 조건

손실이 이미 있거나 새로 증가하면 경고를 활성화한다. 다음 조건을 연속 3,600초 관측해야 경고만 해제한다.

- A/B 센서 데이터가 모두 `FRESH`이고 라이다 드라이버·전처리·송신·오케스트레이터가 모두 `HEALTHY`.
- 송신 상태 파일이 같은 site/edge/config에 속하며 15초 이내에 보고됨.
- 각 센서의 최근 PERIODIC 원본에 대해 획득·생성·ACK 관측 시각이 모두 15초 이내이며, A의 ACK만으로 B를 정상으로 취급하지 않음.
- 최근 PERIODIC과 STATE 각각에 대해 실제 검증된 HTTP ACK가 존재하고, 메시지 생성 시각 및 엣지의 ACK 관측 시각 모두 현재로부터 15초 이내. 오래된 근거 ACK만으로 충족하지 않는다.
- 최근 15초 이내 판단을 관측했고, 현재 스캔·판단 참조가 알려진 손실 근거 ID와 겹치지 않음.
- Outbox 손실 카운터가 동일하고 정상 관측 호출 간격이 3초 이내.

이 15초는 최신 상태/전달 증거의 유효 기간이며 1시간 타이머를 대체하지 않는다. A/B 시간 정합 허용치나 측정 필터는 변경하지 않는다. 전달 성공과 판단 결과의 품질은 별개다.

## 중단·재시작

- 비정상 조건은 정상 관측 시간을 초기화한다. 여러 정상 구간을 합산하지 않는다.
- Outbox 손실 카운터 증가·감소, 필수 서비스 instance 변경, 관측 간격 초과/역행, Stats RPC 실패는 보수적으로 손실 경고를 다시 활성화한다(과거 손실이 있을 때).
- 오케스트레이터의 로컬 상태 파일에서 `loss_high_water`만 복구한다. 재시작 전 정상 시간·해제 여부는 승계하지 않는다. 재시작 또는 설정 세대 변경 후 새로 연속 1시간을 관측한다.
- 누적 카운터가 외부에서 감소해도 로컬 high-water 이력을 낮추지 않는다. 이 로컬 이력은 Outbox 원래 카운터를 덮어쓰거나 복원하는 기능이 아니다.
- 알려진 현재 근거 누락은 경고를 유지/재활성화한다. 보관된 손실 ID 목록은 기존 유한 목록이므로 전체 과거 손실의 역추적 기능을 새로 제공하지 않는다.
- 정상 복귀 후 다른 오류만 발생하면 그 오류의 종합 상태를 유지한다. 모든 서비스를 일괄 `HEALTHY`로 바꾸지 않는다.
- 과거 적체가 0이어야 한다는 조건은 없다.

## 로컬 진단

`edge-orchestrator.json`의 `loss_recovery`에 활성 여부, 손실 high-water, 현재 관측 카운터, 복귀 조건 충족 여부, 연속 정상 초, 필요 초(3,600)를 기록한다. 이 필드는 로컬 운영 진단용이며 백엔드 상태 payload에는 추가하지 않는다.

`measurement-uplink.json`의 종류별 `http_delivery`에는 `latest_accepted_generated_at`, `latest_accepted_observed_at`을 기록한다. PERIODIC/STATE의 ACK 검증 성공 후에만 갱신하고, 늦게 도착한 과거 메시지 ACK가 최신 생성 시각을 뒤로 돌리지 않는다.

## 검증 및 운영 적용

가상 단조 시계로 3,599초/3,600초 경계, 재손실, 상태 이상, 관측 공백, 서비스 재시작, 카운터 감소, 현재 근거 누락, 다른 오류 유지, 과거 메시지 ACK를 재현한다. 실제 Pi 적용 직후에는 경고가 유지되고 타이머가 0부터 시작해야 한다. 연속 정상 1시간을 실제 관측하기 전 운영 경고 해제를 확인했다고 보고하지 않는다.
