# Pi 수집·판단 주기와 보정 API 검증

## 판정

실시간 SDK 입력의 관측 누락과 대기 묶음 폐기를 개선했고, 10분 측정 구간에서 추가 손실은0이었다.
정기 측정·판단의 약1Hz 생성과 보정 API 적용을 확인했다.
수신 간격의 p99≤1.2초·최대≤1.5초 목표는 미달이다. 전체 지연 목표를 통과한 시험으로 표현하지 않는다.

10분 시험의 런타임은 `cda929707f662df93a752a481314e30c0e6ea102`다. 이후 검증 보완에서는
CI 준비·시험 동기화·파일시스템별 시험 크기와 보정 제어기의 저장 확정·복구 처리를 보완했다.
수집·계산·전송 경로는 유지하며, 후속 제어 패치를 전체 10분 시험의 새로운 실행 결과로 위장하지 않는다.
PR: [#15](https://github.com/ajin-scrap-monitoring/ajin-edge-platform/pull/15).

## 변경과 보존 조건

- 전처리 ingest·periodic을 단일 계산 worker에서 직렬화하고 관측/gRPC 이벤트 루프와 분리했다.
- 점 좌표 계산의 반복 배열 할당과 불필요한 deep copy를 줄였다.
- 검증된 canonical JSON의 바이트·길이를 저장 과정에서 재사용한다. 원본 본문과 해시는 바꾸지 않는다.
- 내부 근거 stage는 최대4건·16MiB로 묶고 각 파일 fsync와 마지막 디렉터리 fsync 뒤에만 수락한다.
- HTTP 최대4건 병렬 전송과 ACK 묶음 저장을 적용했다. ACK가 확정되기 전 보호를 해제하지 않는다.
- ACK receipt 순환은 기존 원본의 `.acked.record` rename과 디렉터리 fsync로 확정한다.
  보호된 저장소가 가득 차도 큰 본문을 다시 쓰기 위한 공간을 요구하지 않는다.
- 부분 실패의 lease를 재시도 동안 유지하고, 수집된 ACK 근거도 해시가 같은 본문으로 복구할 수 있다.

최대100ms 시간 정합·1초 입력 만료·판단 대기 묶음1개·기존 센서 이력·4GiB 저장 상한을 늘리지 않았다.
백엔드 장기 보관 책임을 Pi로 옮기지 않았다.

## 실제 입력 600.2초 시험

현재 연결된 시뮬레이터의 실시간 UDP→SDK 드라이버 입력을 같은 Pi의 별도 전처리·uplink·판단·보정 API
컨테이너에서 사용했다. 운영 백엔드에는 시험 설정·판단을 보내지 않았다.
시험 수신기는 별도 프로세스에서 현재 계약을 검증하고 ACK를 반환했다. 실제 백엔드 DB 저장 성능 시험은 아니다.
운영 서비스가 함께 실행된 부하 조건이며 스택 샘플링·개발 테스트는 측정 구간에 실행하지 않았다.

| 지표 | 정기 측정 | 판단 |
|---|---:|---:|
| 생성 구간 메시지 수 | 598 | 599 |
| 생성 간격 중앙값 | 1.001초 | 1.001초 |
| 생성 간격 p99 | 1.053초 | 1.049초 |
| 생성 간격 최대 | 1.063초 | 1.066초 |
| 수신 구간 메시지 수 | 599 | 599 |
| 수신 간격 중앙값 | 0.999초 | 0.998초 |
| 수신 간격 p99 | 1.610초 | 1.555초 |
| 수신 간격 최대 | 3.544초 | 2.044초 |

생성 간격은 generated_at이 측정 구간에 있는 메시지로, 수신 간격은 received_at이 측정 구간에 있는
메시지로 각각 계산했다. 재전송 중복은 제외했다. 1Hz는 정확히600개를 보장하는 하드 실시간 타이머가 아니다.

| 무결성·상태 | 결과 |
|---|---:|
| 관측 누락 추가 증가 | 0 |
| 전처리·판단 대기 메시지 폐기 증가 | 0 |
| 디스크 저장 손실·시험 수신 거부 | 0 |
| EVIDENCE 수신 | 5,990개 |
| 판단의 누락 근거 참조 | 0 |
| 정기 측정의 좌표 포함 점 | 956,800 / 956,800개 |
| 종합 수치 생성 | 478개 |
| 최종 drain 후 전송 대기 | 0 |
| 서비스 세대 변경 | 없음 |

준비·설정 전환 구간에는 관측 구독자가 아직 붙지 않은 누계19개가 있었고, 측정 구간에는 증가하지 않았다.
이 누계를 지우거나 전체 실행의 누락이0이라고 표현하지 않는다. 종료 후 producer를 먼저 멈추고 uplink를 drain했다.
공통 시간 조건·단면 완결성을 만족하지 않은 판단은 LIMITED/UNAVAILABLE와 이유를 유지했다.
시험의 AVAILABLE477개·LIMITED121개·UNAVAILABLE1개는 정확도 인증이나 전부 계산 성공이라는 뜻이 아니다.

수신 지터는 남아 있다. 생성 주기 검증을 근거로 모든 메시지가 매초 정확히 도착한다고 해석하면 안 된다.
정기 값 우선 슬롯을 별도로 배정하는 안도 시험했으나 근거 처리량 저하·묶음 폐기가 재발하여 채택하지 않았다.

## 보정 적용

[보정 API](CALIBRATION_API.md)는 별도 Bearer 토큰·멱등 요청·버전 충돌 검사·오른손 회전 행렬 검사를 적용한다.
새 설정의 백엔드 저장 ACK 뒤 활성화하고, 데이터 서비스3개의 새 revision 적용을 확인해야 APPLIED다.
상태 소실 시 초기 보정으로 조용히 돌아가지 않는다. 제어 폴더는 API에만 쓰기 권한을 제공한다.

격리 시험에서 공개 시뮬레이터 pose를 API로 전달하여 실제 유입 점의 XYZ와 서로 다른 A/B 단면·종합 계산을
확인했다. 내부4개 bin·시험 가중치·항등 곡선은 운영 용기 전체의 적재율 보정값이 아니다.
운영에는 검증된 보정 요청만 적용한다. 보정이 없거나 UNVERIFIED면 좌표는null이며 가짜 z를 채우지 않는다.

기존 운영 백엔드의 judgment·section_profiles·fusion_result 수용은 별도 연동 작업이다.
이 API가 백엔드 검증을 우회하거나 판단 모델을 임의 생성하지 않는다.

## 회귀·복구

ACK 순환·저장 상한·fsync 실패 후 재시도, 부분 stage 실패·lease 만료 후 복구, 설정 ACK·재시작·적용 경계,
기존 원본·시간·A/B 독립 계산 회귀를 확인한다. CI는 Python3.13.11과 uv0.9.28을 고정한다.
Linux tmpfs/overlay와 Windows의 실제 할당 단위 차이는 시험 저장소 크기를 실측하여 반영한다.

구형 이미지로 복구할 때에는 writer를 모두 중지하고 `.acked.record`의 ACK 상태를 구형 본문 형식으로
내구 변환한 뒤 시작해야 한다. 단순히 이전 큐 백업을 덮어쓰지 않는다. 운영 교체는 기존 큐를 보존하며
이전 이미지·설정과 정지 시점 스냅샷을 확보한다.
