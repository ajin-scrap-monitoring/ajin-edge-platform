# 엣지 v2 구현 계획

기준: `edge-lidar-orchestration-plan/03_백엔드_연동_규격_v2.md` (2.0-r1).
기존 v1 경로·운영 DB는 그대로 두고 v2를 명시적으로 선택하는 실행 경로를 추가한다.
이 작업은 로컬 구현·검증이며 운영 배포·백엔드 구현을 포함하지 않는다.

## 순서

1. 공통 계약과 처리 엔진: 원본 보존, 검증된 R/t만 적용, 1초/100ms 선택,
   소비한 스캔 중복 방지, 기계 검증 및 경계 테스트.
2. 전송: 네 API, 저장 ACK 확인, 오류별 처리, 토큰 교체, 제한된 재시도.
3. 저장: v1과 별도 저장소, 실제 파일 예산, 원본 격리, 공유 근거 참조와 정리.
4. 오케스트레이션: 모든 관측 입력, 중단/복구, 미구현 판단 명시,
   사건 개정·근거 인터페이스, 상태 보고.
5. 드라이버와 서비스 연결: 수집 시 ID·시각, 설정 ACK 활성화 게이트,
   독립 서비스 실행 경로와 Docker 실행 문서.
6. 통합 검증: 기존 회귀, 새 계약/오류/복구 테스트, 최종 변경 검토.

각 단계는 실패하는 테스트를 먼저 실행한 다음 구현하고 전체 회귀를 실행한다.
실제 보정값·검증된 판단 규칙·운영 URL/토큰은 생성하지 않는다.
미디어 스트림 확장·모델 추론의 미확정 세부 규격은 이 작업에서 임의 확정하지 않는다.

## 검토 초점

- API별 ACK와 설정 ACK를 혼동하지 않으며 수신 ACK를 원격 저장 ACK로 취급하지 않는다.
- 과거 근거에는 최신성 제한을 재적용하지 않는다.
- 품질값으로 점을 제거하거나 미검증 좌표·적재율을 생성하지 않는다.
- 모든 저장 파일·정리 중 임시 파일을 예산에 포함한다.
- 오래된 큐와 공유 근거가 무한 대기하거나 무단 삭제되지 않는다.
- v1 DB와 운영 서비스는 자동 전환하지 않는다.
