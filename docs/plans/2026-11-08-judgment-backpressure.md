# 판단 묶음 대기열 폐기 수정 계획

목표: 실제 입력에서 재현한 LOCAL_DELIVERY_BACKLOG_LOSS 경로를 수정하고 Pi 재시험·CI 뒤 main에 병합한다.
기존 worktree에서 직접 구현하고 완료 전 독립 검토를 수행한다.

## 원인과 보존 조건

기존 PendingSender.offer는 대기열1개가 차면 이전 묶음을 무조건 폐기한다.
실제 SDK 입력에 저장 stage3초 지연을 한 번 주입했을 때11메시지 묶음2개의 폐기를 계측했다.
INVALID_ARGUMENT/ALREADY_EXISTS 거부는 이 재현의 원인이 아니었다.
이전 단일 사건은 당시 상세 계측이 없어 정확한 발생 시점을 소급 확정하지 않는다.

대기열1개, 처리 중1개, 최근 스캔 이력·입력 만료·시간 정합과4GiB 임시 저장 한도를 유지한다.
대기 공간을 얻은 뒤에만 새 판단을 계산하여 추가 완성 묶음을 메모리에 쌓지 않는다.
전처리 정기 전송·원본 선택·판단 수식·백엔드 계약·기본값은 변경하지 않는다.
지연 때에는 생성 간격이 늘어날 수 있으며, 1초 정확 도착이나 장기 무손실을 주장하지 않는다.
