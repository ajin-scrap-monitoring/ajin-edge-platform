# 오케스트레이션 단면 판단 구현 계획

목표는 선택 구간 원본 관측의 전송을 유지하면서 별도 관측 사본으로 필터링, 공간 및 시간 중앙값, 제한 보간, A/B 단면 융합과 보정 적재율을 계산하는 것이다.

## 설계와 제약

- 전처리 PERIODIC의 점, 시각, 인덱스, 품질과 선택 정책은 변경하지 않는다.
- 등록 설정에 선택적 judgment를 추가한다. 보정 행렬, 단면 기준선, 바닥 및 상한 높이, 필터 임계치, 시간 창, 적재율 보정곡선을 명시한다. 예제는 합성 입력이며 현장 기본값으로 사용하지 않는다.
- 공통 좌표의 단면 축에 투영한 일정 폭 bin을 사용한다. 품질/거리/SDK 무효값/평면/높이 범위 검사 후 bin 중앙값, 선택적 공간 이상점 제거, 최근 스캔의 시간 중앙값을 계산한다.
- A/B 최신 쌍은 동일 단조 시계에서 100ms 이내여야 한다. 입력은 1초 이내이고 센서별 최소 스캔 수를 충족해야 한다. 인스턴스 변경과 수집 공백은 이력을 분리한다.
- A/B가 같은 bin에서 불일치하면 충돌로 표시한다. 내부의 짧은 빈 구간만 보간하고 마스크, 충돌, 양끝, 긴 빈 구간을 넘지 않는다.
- 단면 면적비와 보정 적재율은 별개다. 검증된 설정과 설치 보정에서만 수치 판단을 활성화하고, 보정곡선이 없으면 단면만 제공한다. 부피율로 임의 해석하지 않는다.
- 선택적 section_profile로 판단 단면과 근거를 전송한다. 기존 measurements JSON은 그대로다. 새 configuration/assessment 필드는 백엔드 확장 사항으로 문서화한다.
- 실제 사용 관측은 EVIDENCE로 먼저 로컬 저장 요청하고 판단을 뒤에 넣는다. 전달 묶음은 유한 큐로 관리하고 실패/초과를 보고하며 원본 전송 프로세스를 기다리게 하지 않는다.

## 구현 순서

- [x] 합성 입력 회귀 테스트 작성 및 실패 확인
- [x] 판단 설정 검증과 순수 단면 계산 모듈 구현
- [x] Orchestrator 이력, 상태, 계산 결과와 EVIDENCE 연결
- [x] runtime 전달 묶음과 독립 주기 실행 연결
- [x] 공개 JSON Schema 및 백엔드 변경 문서 갱신
- [x] 누락, 시계 불일치, 인스턴스 변경, 충돌, 보간 경계, 원본 불변성과 실제 세 서비스 연동 검증
- [x] 전체 테스트, 린트와 Pi 격리 컨테이너 검증

## 검토 중점

원본 변경, 오래된/다른 시계 스캔 혼합, 과도한 보간, 미검증 설정의 수치 출력, 사용 근거 누락을 우선 확인한다. 운영 설정과 주소는 저장소에 포함하지 않는다. 이번 구현은 녹화 저장 경로와 카메라 서비스를 변경하지 않는다.
